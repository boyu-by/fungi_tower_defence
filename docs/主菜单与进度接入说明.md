# 主菜单与关卡进度

## 使用方式

项目默认入口为 `res://scenes/ui/main_menu.tscn`，运行项目进入标题页。界面按策划提供“开始游戏”“继续游戏”“退出游戏”。当前标题暂用“菌脉”，插图复用素材库中的母核蘑菇，后续可替换。

- 开始游戏：从第一关重新开始；已有第二关以上进度时，先确认是否重置。
- 继续游戏：进入最近解锁关卡的初始状态。没有有效记录时禁用；通关后可继续挑战第三关。
- 退出游戏：关闭应用。

进度按真实关卡结算解锁：第一关胜利解锁第二关，第二关胜利解锁第三关，第三关胜利记录通关。重开旧关不会倒退“继续游戏”的目标。每关使用自己的初始生命、养分和网络，不继承上一局资源。

开始游戏先播放CG1，第一、二关胜利继续分别播放CG2、CG3；第三关结尾播放CG4后显示通关结算。图片序列配置与操作见 `docs/CG占位与图片替换说明.md`。继续游戏仍直接进入最近解锁关卡，不保存逐段观看记录。

## 关卡内界面

三关左上角显示本关目标、母核生命和养分。顶部新增“菜单”，更多页也提供“游戏菜单”入口。

暂停菜单提供继续、重新开始、返回主菜单和退出游戏。打开时冻结世界并拦截建设、重开等游戏快捷键；Esc关闭菜单。若此前已用Space手动暂停，关闭菜单后保持规划暂停，按钮显示“返回暂停规划”；正常运行中打开则显示“继续游戏”。

Space仍是原有的规划暂停，不自动弹出遮挡地图的菜单，暂停中的观察、选择和预览保留原行为。失败与通关结算保留重开、下一关等原按钮，并补充返回主菜单和退出游戏。

返回标题前停止旧局生产和任务，禁用旧世界与系统，再解除全局暂停并切换场景。重开和再次进入关卡均创建新实例，不接收旧局任务。退出应用与返回标题使用不同按钮，含义明确。

## 保存范围

记录文件为 `user://campaign_progress.cfg`，位于Godot的用户数据目录，不在仓库中。

当前字段为版本、最高解锁关卡、继续目标关卡和通关标记。通过临时文件写入后替换正式文件；不存在、损坏或版本不支持的记录禁用继续，并允许开始新游戏。不保存局内布局、战斗波次、生命、养分、成长、任务或在途运输。

主线导航节点 `CampaignFlow` 由标题流程按需创建，跨场景保留，不添加项目autoload。直接F6运行关卡不会写主线记录，避免调试或现有测试改变玩家进度；这些关卡仍可以通过菜单返回标题。F5～F10旧开发入口保持可用。

## 代码与美术接入

| 文件 | 职责 |
| --- | --- |
| `scenes/ui/main_menu.tscn` | 可编辑标题布局、名称、插图与三个按钮 |
| `scenes/ui/level_menu.tscn` | 可编辑暂停遮罩、提示和菜单按钮 |
| `resources/ui/menu_theme.tres` | 菜单字体、按钮状态、边框和面板配色 |
| `scripts/main_menu.gd` | 标题按钮意图、进度提示与重置确认 |
| `scripts/campaign_progress_store.gd` | 小型进度文件的校验、写入与解锁 |
| `scripts/campaign_navigator.gd` | 开始、继续、返回标题及主线结算接线 |
| `scripts/level_menu_layer.gd` | 暂停菜单、输入拦截和结算返回按钮 |

美术可替换标题场景中的 `Artwork.texture`、背景视觉节点、标题文本及共用Theme；保留按钮、进度标签和确认框的现有节点路径。暂停菜单同样保留节点路径与信号意图。结算新增按钮沿用当前代码生成方式，样式由共用Theme控制，位置由 `LevelMenuLayer` 配置。

四段CG已接入开始入口、两次关间切换和第三关结尾，共用 `StoryPlayer` 与四份可替换资源，不改动关卡战斗算法。

## 验收

`tests/main_menu_test.gd` 使用工作目录内的隔离进度文件，覆盖缺失/损坏记录、保存失败、解锁、重复操作、确认重置、真实菜单点击、三关暂停、带建设任务返回、失败退出、CG4结算返回与退出应用意图。胜利与终局部分使用明确的隔离夹具，不代表正常通关平衡记录。

2026-10-17：菜单56项，九组原有回归6622项，合计6678项通过。回归包含现有面板、暂停、第一关集成、开发导航、第二关、第三关、共用基础、六波与敌人批次。默认启动和图形运行均无脚本错误，核对标题、继续提示、暂停和失败界面。

验收摘要见 `tests/evidence/main_menu_acceptance.json`。
