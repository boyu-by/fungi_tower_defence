# 三关策划与程序交付需求

共用结构基线：`3f6f5ca`。当前默认入口为标题菜单 `res://scenes/ui/main_menu.tscn`；第一关场景为 `res://scenes/levels/first_level.tscn`，第二关场景为 `res://scenes/levels/second_level.tscn`，第三关场景为 `res://scenes/levels/third_level.tscn`。

现有第一关沿用已完成的六波、地图、敌人阵容与操作，不另建综合测试关。第二、三关使用独立场景与配置。第4节保留早期基础教学方案，供后续评审参考，不作为本轮改写现有第一关的任务。时间、养分、设施生命、敌人属性及配比均配置化，通过试玩调整。

## 1 目标与交付范围

### 1.1 三关主线

明确要求：

`标题 → CG1 初次绘画 → 第一关 → CG2 AI冲击 → 第二关 → CG3 成年后的思考 → 第三关 → CG4 与自己和解 → 通关界面`

| 关卡 | 胜利目标 | 主要体验 | 难度递进 |
| --- | --- | --- | --- |
| 第一关 初步绘画 | 清除六波敌人并保持母核存活 | 建立防线，理解养分循环 | 基础供养与火力布局 |
| 第二关 AI冲击 | 摧毁地图上的三台AI并保持母核存活 | 从防守转向反攻 | 前沿保护、持续生产和线路恢复 |
| 第三关 自我和解 | 收集三个角落的碎片并保持母核存活 | 安排资源与探索路线 | 多方向建设与持续防守 |

### 1.2 程序交付物

1. 三个能够独立启动、独立重开的正式关卡场景。
2. 各关独立地图与可编辑配置；第二、三关保留普通、小型群体、重甲，将啃食者拆为菌丝型与菌结型，共五种敌人，配置与第一关原阵容隔离。
3. 第一关六波流程，第二关AI生产与摧毁目标，第三关碎片收集与无限波次。
4. 各关目标HUD、教学提示、暂停、失败与结算。
5. 标题、四段CG的占位流程及关间切换；美术可后换。
6. 必要的定向自动检查与正常游玩记录。
7. 保留现有第一关及其已有功能；开发场景文件按现有继承依赖保留。

第一关使用现有 `first_level.tscn`，第二关使用 `second_level.tscn`，第三关使用 `third_level.tscn`。各关独立维护地图和目标。

### 2.1 正式关卡接入边界

- 当前`FirstLevel`沿用已有继承链；第二、三关继承共用基础场景和`ColonyLevelRuntime`，不继承`FirstLevel`或各演示脚本。
- 共用运行层按实际实例登记菌结和器官；默认观察对象可通过`initial_attack_organ`、`initial_digestive_organ`指定，未指定时自动寻找。新地图无需沿用旧菌结名称。
- 母核可按关卡更换贴图、动画、视觉子节点及外观状态；保留`World/Colony/MotherCore`节点、`MotherCore`功能脚本及其生命、营养、受击、信号接口，使共用系统继续接线。若更换整个母核场景，需核对这些接口和HUD所需子节点。
- 共用层的`normal_weapon_profile`、`growth_planner`、`enable_colony_operations`和运营面板配置由各关按需要设置。功能分关开放还需额外实现能力约束，不能仅隐藏按钮。
- `FirstEventGuide`已有文本包含特定资源方向和现有敌人分工，正式关必须换为本关文案。
- `FirstLevelFlow`固定六波，第一关可复用其流程能力，但使用自己的波次资源；第二、三关另建持续生产控制器。
- `SporeWeapon`、`SporeProjectile`、`CombatTargetingSystem`以及`EnemySpawnEntry`绑定`BasicEnemy`。AI设施不能仅添加一个普通`Node2D`就期望被自动攻击。
- `EnemySpawner`以单批次状态、身份和计数管理生成。必须设计持续生产适配层，不能通过随意reset掩盖上一批存活敌人。

### 2.2 现有功能修改项 啃食者拆分

仅拆分现有啃食者，保留普通、小型群体和重甲敌人的现有能力。修改后正式敌人库共五种；敌人的种类与攻击组织分类是不同维度，不能因为组织分类而删去群体和重甲。

| 敌人 | 行为与作用 | 修改范围 |
| --- | --- | --- |
| 普通敌人 | 保留现有基础进攻行为 | 不因啃食者拆分改写第一关现有行为；新关通过独立配置接入 |
| 小型群体 | 保留低生命、快速、成组出现的特性 | 保留场景、属性、群体生成和散射应对关系 |
| 重甲敌人 | 保留高生命、护甲与较慢移动 | 保留护甲结算、场景和破甲应对关系 |
| 菌丝啃食者 | 从原啃食者拆出，只直接攻击菌丝 | 独立目标搜索、场景与出怪配置 |
| 菌结啃食者 | 从原啃食者拆出，只直接攻击菌结 | 独立目标搜索、场景与出怪配置 |

两种啃食者的行为要求：

- 菌丝型只搜索并损伤存活、可达的菌丝，复用沿边选择可达攻击位置与接触检查；不能顺带损伤端点菌结或器官。
- 菌结型只搜索并损伤存活、可达的菌结，不能改为攻击连接菌丝或宿主器官。
- 没有合法目标、目标死亡或暂时不可达时，重新搜索同类目标或待机，不回退攻击其他组织。
- 复用现有寻路、重选和接触检查，避免频繁切换目标；有无地形都维持各自目标限制。
- 菌结受损导致器官停用、断丝导致物流暂停等间接影响，继续遵守现有组织规则。
- 保留正常受击、弹丸命中、死亡与唯一尸体生成。参数独立配置，不增加新的资源结算系统。

程序修改范围：

1. 在`basic_enemy.gd`或独立模块中为啃食者增加可区分的菌丝、菌结目标策略，不改写普通、小型和重甲的现有行为。
2. 创建两份独立啃食者场景及对应`EnemySpawnEntry`资源。
3. 第二关AI生产与第三关持续出怪支持全部五种敌人；不再使用同时攻击菌丝和菌结的原啃食者作为正式阵容。
4. 保持`BasicEnemy`兼容，使现有武器、弹丸、出怪计数、死亡回收和在途伤害协调继续有效。
5. 原`GNAWER`与混合目标行为保留为第一关兼容项，不计入第二、三关的五种敌人。新增策略不能无条件改变旧实例；扩展枚举不得改变既有序号对应关系。
6. 更新两种啃食者的提示和教学，同时保留小型对应散射、重甲对应破甲的战斗分工。各关是否教学由实际出场顺序决定。

新增验收：同一地图放置母核、菌丝、菌结、器官、幼芽和尖端，验证两种啃食者只攻击各自合法组织，其他对象更近时也不跨类。覆盖无目标、目标死亡、断连、不可达、恢复、暂停、重开和重复死亡。普通、小型、重甲原有行为与护甲、群体生成、武器克制继续通过回归；现有第一关仍可运行。

## 3 共用玩法与流程要求

### 3.1 资源与成长

已有规则继续使用：击杀后形成尸体，菌域采集，经网络运到胃囊，消化形成回流，抵达母核后增加余额与累计回收。

- 保留一种可支配资源，不为AI或碎片新建经济货币。
- 初始养分、退款、内部转运不计入累计回收。
- 保留累计回收60开放双尖端、160开放第二消化腔的规则。
- 主脉继续按确认的有效货物通过量成长；关卡奖励不能伪造运输历史。
- 每个关卡独立配置初始资源与组织，不能修改第一关初值来方便新关通关。

### 3.2 关卡状态

建议统一状态：`准备 → 游玩 → 胜利或失败 → 切换或重开`。暂停作为独立状态标记，不丢失当前关卡阶段。

- 母核归零立即判负；同帧主目标完成时失败优先，与现有第一关保持一致。
- 结算只触发一次，先保存快照，再停止任务与冻结世界。
- 未完成建设、未回流产物、未清完敌人不能阻止第二、三关目标胜利。
- 失败、胜利或切关后不接收旧局回调；旧生产、货物、预留、目标收集不能改变新局。
- 重开恢复该关初始配置，清空目标、建设、生产、收集进度与本局引导记录。

### 3.3 暂停与界面

复用已有全局暂停语义：冻结世界、出怪、运输、消化、生长、修复、分化、移植及收集计时；界面允许观察与选择。

- 暂停时预览不扣资源、不建立待恢复自动执行的隐藏指令队列。
- 恢复后确认操作需重新提交。
- 若需要暂停式教学，提示开启前记录原暂停状态，关闭后恢复原状态，不能把玩家手动暂停错误解除。
- 胜利后世界被冻结，但CG与切关按钮仍能运行；新关启动前清除全局暂停残留。
- 基础HUD显示母核生命、养分、波次与本关目标。累计回收简洁显示；运输明细按需展开。
- 提示说明具体原因，例如失联、缺粮、胃囊接收容量满或收集暂停。

### 3.4 功能开放

试作建议：第一关突出基础选择、生长、攻击培育和养分循环；第二关开放互连、修复和前沿运营；第三关综合使用。

第一关哪些高级操作隐藏或禁用，属于可调的教学取舍。第一关保持基础教学；第二、三关保留群体与重甲，按出场顺序介绍散射和破甲。实现时使用关卡能力配置；禁用既要约束按钮，也要约束快捷键与提交入口。不得删除核心模块来实现“本关不开放”。

## 4 第一关 初步绘画（早期基础教学参考方案）

### 4.1 策划目标

本节是早期基础教学方案：只出现普通敌人，且只攻击母核，清除六波获胜。当前实际第一关继续使用已经完成的四类混合波次；本轮第二关开发不按本节重做第一关。

体验：玩家观察预建防线，理解射击消耗与尸体回收，再完成一处火力建设和一次资源扩张。

### 4.2 地图与开局

试作建议：

- 母核位于后方中央，胃囊靠近母核，减少首次回流等待。
- 两个基础攻击器官位于左右前方，覆盖主要接近路径。
- 前方设置一个空菌结，用于培育教学，并填补火力空隙。
- 侧面初始菌域外放一处资源尸骸，适合短距离扩张。
- 入口依次引入正面、左前与右前方向。方位用于表达关系，具体地图构图由关卡制作确定。
- 前两波主要击杀位置位于有效菌域内，保证回收教学成立。

| 参数 | 试作初值 | 说明 |
| --- | --- | --- |
| 母核生命 | 240 | 沿用现有基础 |
| 初始养分 | 72 | 沿用现有基础 |
| 攻击器官 | 2个，各4点启动库存 | 与母核连通 |
| 胃囊 | 1个 | 使用正常消化与回流 |
| 侧面尸骸 | 40养分 | 是否在第一关加入该资源点为试作建议 |
| 清波整备 | 15～20秒 | 教学提示不挤占操作时间 |

### 4.3 六波节奏

波数固定为6，各波只使用普通敌人。下表规定节奏意图，具体数量和属性通过试玩调整。

| 波次 | 布局与压力 | 教学目标 |
| --- | --- | --- |
| 1 | 单方向、低压力 | 观察自动攻击与首次回收 |
| 2 | 保持单方向，适度增加压力 | 理解库存、补给和回流 |
| 3 | 引入第二方向 | 引导补建火力 |
| 4 | 两侧交替进入 | 引导接通资源，利用收入 |
| 5 | 多方向但保留缓冲 | 检验火力与持续供养 |
| 6 | 多方向分批收尾 | 综合运用本关已教学能力 |

出生数量、速度、攻击、生命、尸体价值与各波间隔作为可调参数。用独立资源保存，不直接改`resources/first_level_waves/`现有测试配置。

### 4.4 教学与结算

| 触发 | 提示目的 |
| --- | --- |
| 开局 | 说明目标与母核死亡失败 |
| 首次射击 | 解释本地库存与沿网补给 |
| 首次尸体送达 | 解释胃囊消化过程 |
| 首笔回流抵达 | 解释可用收入与累计回收 |
| 第二波后 | 引导在空菌结培育，已完成等效操作则跳过 |
| 第三波后 | 指向资源点，引导生长与覆盖 |

胜利需六波全部计划成员已生成、全部正常击败、真实存活为零。删除敌人、停止批次或旧回调不算清波。结算显示母核剩余生命、累计回收、完成波数与游戏时间，随后接CG2。

### 4.5 复用与验收

- 复用六波流程、暂停、重开与结算；第一关引导替换成专属配置。
- 接入第一关专用普通敌人配置，验证6波、整备、开始按钮和重开，再进行正常战斗平衡验收。
- 必须验证：不出现第7波；连续点击不重复开波；新玩家能取得真实回流；合理建设后能通关；未完成建设不阻止结算。

## 5 第二关 AI冲击

### 5.1 策划目标

明确要求：敌人无限波次，地图有三台持续生产敌人的AI，网络需要向外生长，击败三台AI后获胜。敌人库采用普通、小型群体、重甲、菌丝啃食者与菌结啃食者五种，两种啃食者分别直接攻击对应组织。

试作建议：玩家通过生长建立前沿攻击器官，以正常射击摧毁AI。菌丝接触AI本身不直接造成伤害。目标交互与养分系统分离，调整交互方式时不重写养分系统。

### 5.2 地图与开局

- 母核位于后方中央，AI分别位于左前、中前和右前区域。
- 左侧较易接近、中间需要保护运输、右侧承担最终推进；允许其他顺序。
- 支路间有可互连位置，已有据点可以成为继续推进的起点。
- 资源点放在途中，不把全部收入集中到最后设施后方。
- 预览能看出器官是否覆盖目标，避免建成后才发现无法射击AI。

| 参数 | 试作初值 |
| --- | --- |
| 母核生命与养分 | 240生命、90养分 |
| 初始组织 | 2个攻击器官、1个胃囊、基础连通网络 |
| 尸骸 | 2处，各80养分 |
| AI生命 | 左120、中180、右240；作为可调占位值 |
| 初始准备 | 30秒 |
| 生产周期 | 35秒，五种敌人的批量与比例可调 |

### 5.3 AI设施要求

| 事项 | 行为要求 |
| --- | --- |
| 身份 | 三个稳定目标ID，各自独立生命与生产状态 |
| 表现 | 蓄能、预警、生成、冷却、摧毁可区分 |
| 出生 | 固定合法出生点，不能与玩家组织重叠或落在障碍中 |
| 受击 | 复用正常武器、弹丸和伤害结算，不用调试伤害按钮通关 |
| 选敌 | AI可被选择为优先目标；普通自动选敌仍可工作 |
| 摧毁 | 同一设施只发布一次摧毁事件，永久停止该设施生产 |
| 奖励 | 首轮不自动赠送大量养分，不把设施残骸当普通敌尸重复结算 |
| 胜利 | 三个不同ID均确认摧毁且母核存活，立即胜利 |

设施死亡不得被普通出怪器误算为清波成员，也不得触发普通敌尸生成链，除非以后明确设计了该收益。

### 5.4 无限生产与推进节奏

- “无限”表示没有固定波数终点，并非数量或属性无限上涨。
- 到达压力上限后保持稳定。上限与五种敌人比例通过试玩调整。
- 不要求清空上一批后才继续生产，维持主动进攻动机。
- 摧毁AI后取消其尚未出生的成员；已出生敌人保持原身份继续行动。
- 剩余AI不自动增产抵消摧毁收益。
- 试作建议：设施摧毁后让全局下一次生产至少延后20秒，形成可感知的整备回报。
- 正常暂停冻结生产倒计时；恢复不集中补发暂停期间的批次。

推荐阶段：接左侧资源并建立据点 → 摧毁最近AI → 保护或恢复中间线路 → 接通旁路 → 推进最后设施。步骤用于引导，不作为强制任务链。

试作建议：初期以普通敌人为主，随后逐步加入菌丝型和菌结型，首次出现时分别说明“线路受威胁”和“据点受威胁”。三台AI的配比可不同，但不能继续使用原啃食者同时威胁两种组织。同时保留小型群体、重甲的出场与对应分化提示，玩家未推进时也通过时间兜底引入后续类型。

### 5.5 实现适配与验收

- 新增设施目标系统、设施生产控制和摧毁胜利条件。
- 对现有攻击目标类型做最小兼容适配。可采用统一战斗目标接口或经过验证的`BasicEnemy`兼容设施，但不能默认继承就自动符合设施语义。
- 适配必须保留在途伤害协调、普通敌人行为、弹药扣费及普通尸体唯一生成。
- 持续生产可用独立出怪实例或新调度器；最终选择由程序实现。不能重置仍有活敌的原单批次来制造“下一波”。
- 设施周围不可达或无有效攻击时给出清楚提示；AI血量不能通过正常生产自动恢复。
- 验收：三台各独立生产；重复死亡不重复计数；摧毁一台只影响其来源；暂停无补发；最后设施摧毁即结束；至少两种攻击顺序可完成。

## 6 第三关 自我和解

### 6.1 策划目标

明确要求：无限波次，三个角落各有一个碎片，收集完成播放CG4并获胜；地图有大型尸骸提供养分。

体验：玩家安排先资源后目标、顺序探索或双线建设，在持续压力下保持后方与长距离网络稳定。敌人不通过无限属性增长迫使玩家赶时间。

### 6.2 地图与开局

- 母核位于中央偏后，左上、右上和右下为三个探索区域，余下区域作为后方缓冲。
- 目标方位从开局可见，不要求盲目搜索。
- 三条路线有互连机会，不做成完全隔离的长走廊。
- 一个近处资源支持首次探索；侧面资源形成绕路选择；最终资源位于最后目标之前，收益能够用于通关。
- 敌人出生点与母核、碎片收集点保持合理分离，并提供预警。

| 参数 | 试作初值 |
| --- | --- |
| 母核生命与养分 | 240生命、100养分 |
| 初始组织 | 3个攻击器官、1个胃囊、三条短支路 |
| 大型尸骸 | 近处80、中央或左侧80、右侧80、远端120 |
| 初始准备 | 25秒 |
| 持续出怪周期 | 30秒，五种敌人的数量与比例可调 |
| 收集时间 | 每个5秒 |

### 6.3 碎片收集规则

试作建议：碎片被有效菌域覆盖，且覆盖来源连通母核时，累计收集时间。实现必须判定有效状态，不能只看画面上的灰色残影。

- 每个碎片具有唯一ID和独立进度。
- 多个来源覆盖同一碎片不叠加速度。
- 失联或失去有效覆盖时暂停，保留已完成进度；恢复后继续。
- 已收集碎片永久保留，不因断路丢失。
- 不扣养分，不创建尸体，不占胃囊或运输容量，不增加累计回收。
- 计时受全局暂停、终局和场景卸载控制。
- 收齐三个不同ID且母核存活即结束，重复事件不触发第二次CG4。

优先复用`FungalField.get_collecting_nodes()`获取有效候选，并核实网络可达和组织功能状态。只调用`is_covered()`或检查视觉范围不能替代连通要求。

### 6.4 三个区域的玩法

| 区域 | 策划作用 | 关卡布局 |
| --- | --- | --- |
| 左上 初次创作 | 建立探索方法 | 较易接近，途中有资源，先接资源再取碎片的路线清楚 |
| 右上 坚持创作 | 选择资源与线路 | 直达路线和侧面资源并存，可从已建区域互连 |
| 右下 自己的选择 | 综合运用 | 最终资源在碎片之前，允许复用其他方向的前沿与网络 |

采用第二关的五种敌人。试作建议：左上以普通敌人为主，右上增加菌丝型与小型群体，右下混合重甲与菌结型；比例可调。保留群体、重甲与分化的战斗分工，不使用原混合目标啃食者。

碎片短句为试作文案，独立成立，不限制顺序：

1. 我还记得，第一次画出自己的世界时，那种快乐。
2. 后来，我也有过怀疑。可我仍然一次次拿起画笔。
3. 现在，我想画什么，就继续画下去。

### 6.5 无限波次与结尾

- 生产不等待清敌，沿用第二关通过验证的持续出怪机制。
- 根据游戏时间与收集进度增加压力，到上限后保持；不收集也有时间兜底，收集也不造成同帧突发大军。
- 试作建议：每收集一个碎片，将下一批生成延后至至少15秒之后，供阅读与整理。
- 敌人库保留五种，各批次按配置选择；数量、属性、配比和入口升级通过试玩调整。
- 第三块完成后立即停止战斗，短暂展示完成的网络，再播放CG4。
- 不要求清敌、采完资源或达到成熟阶段。

验收：任意顺序可收集；重叠覆盖不加速；残影不收集；失联可续接；多线探索与顺序探索都有可行路线；最后目标完成后不额外等待清场。

### 7.3 统一目标快照建议

```gdscript
# 以下信号由各关目标控制器新增；共用结算接口已实现。
signal objective_changed(snapshot: Dictionary)
signal victory_candidate(evidence: Dictionary)

# snapshot中的通用字段：
# level_id, objective_kind, completed, total, state
# evidence必须能核对本局身份与目标实际完成情况。
```

- 第一关：`completed`为完成波数，`total=6`。
- 第二关：`completed`为摧毁设施数，`total=3`，证据保留设施ID。
- 第三关：`completed`为已收集碎片数，`total=3`，证据保留碎片ID。
- 目标模块在真实目标完成后调用关卡根节点的`finish_level(true, evidence)`。该调用延后结算，同一轮回调中母核死亡优先；目标模块不直接播放CG或冻结游戏。
- 母核生命归零由共用层自动提出失败。`level_finished(snapshot)`只发出一次，`get_result_snapshot()`返回独立副本，包含胜负、母核生命、有效游戏时间、累计回收、目标证据和资源快照。
- 共用层在结算前发出`level_stopping(reason)`，并在终局冻结`World`与`Systems`。各关目标、AI生产和碎片控制器监听停止通知，重开或切关时也停止本局计时、生成和回调；CG与切关控制器放在可继续运行的位置。

## 11 敌人要求与可调参数

### 11.1 敌人要求

1. 正式敌人库共五种，仅拆分啃食者，保留其他三种。
2. 第一关保持当前已完成的四类混合阵容，不通过第二关开发改写其敌人行为。
3. 第二、三关支持普通、小型群体、重甲、菌丝啃食者、菌结啃食者，实际比例配置化。
4. 原啃食者拆成两种独立敌人，实现两套互斥目标行为，不只换外观。
5. 小型群体与重甲保留为正式可用敌人；原混合目标啃食者保留第一关兼容。

敌人属性、尸体收益、数量、比例与引入时间通过试玩调试。拆分范围与验收见2.2节。

### 11.2 首轮试玩调整项

- 第一关侧面尸骸与功能开放范围。
- 五种敌人的工作名称、生命、速度、伤害、搜索参数与各关配比；名称变化不改变两种啃食者的组织分工。
- 各关初始养分、尸骸总量与整备时间。
- AI的射击摧毁方式、优先目标操作与设施生命。
- 碎片有效覆盖持续收集方式与短句。
- “继续游戏”首轮只记录关卡进度的范围。

交付记录应列出实际采用的配置与试玩结果。
