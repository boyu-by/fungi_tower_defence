# 关卡复用基础接入说明

## 1 入口与职责

正式关卡从 `res://scenes/gameplay/colony_gameplay.tscn` 创建继承场景。它提供共用系统、母核、空地图容器和基础HUD，不包含测试关的初始器官、资源点、地形、出生点、六波或开发跳转。

共用运行层不继承任何演示脚本：

```text
ColonyRuntime
  └─ ColonyTerrainRuntime
       └─ ColonyOperationsRuntime
            └─ ColonyLevelRuntime
```

| 文件 | 职责 |
| --- | --- |
| scripts/gameplay/colony_runtime.gd | 网络、建设、培育、供养、回收、成长、分化、修复接线与原生命周期 |
| scripts/gameplay/colony_terrain_runtime.gd | 可选地形、前沿状态、敌人组织攻击接线 |
| scripts/gameplay/colony_operations_runtime.gd | 器官选择、改向、移植与运营操作 |
| scripts/gameplay/colony_level_runtime.gd | 无关卡目标假设的运行入口、暂停、计时、资源观察与通用结算 |
| scenes/gameplay/colony_gameplay.tscn | 共用节点与引用，不拥有具体地图和目标 |

当前应用入口为标题菜单 `scenes/ui/main_menu.tscn`；第一关独立入口仍为 `scenes/levels/first_level.tscn`。该关继续经过 `level_01.gd` 等兼容脚本，保留已有资源、快捷键、窗口处理、教学、批次与结算。第二关 `scenes/levels/second_level.tscn` 和第三关 `scenes/levels/third_level.tscn` 直接继承共用基础。第三关的碎片、持续出怪与CG4占位见 `docs/第三关接入说明.md`；主菜单、暂停和进度接线见 `docs/主菜单与进度接入说明.md`。

## 2 制作独立地图

在 Godot 中打开基础场景，选择“新建继承场景”，保存为各关自己的场景。保留以下基础容器及系统路径：

```text
World
  Colony
    MotherCore
    Nodes
    Connections
  FungalField
  Enemies / Projectiles / Remains / SpawnPoints
  各类运输、建设与目标容器
Systems
  共用生长、培育、供养、回收、运输、成长、修复和分化系统
HUD
```

地图由关卡编辑器配置：

1. 将菌结实例放到 `World/Colony/Nodes`，菌丝实例放到 `Connections`，设置实际起终点。
2. 在菌结下放置攻击器官及武器、胃囊等场景。武器设置库存宿主、敌人容器、弹丸容器及协调选敌系统；胃囊设置母核等必要引用。
3. 将资源实例放到 `World/Remains`，出生点放到 `World/SpawnPoints`。
4. 可选地形节点命名为 `World/TerrainNavigation`，可选前沿显示节点为 `World/FrontierStatus`，运行层会自动接线。
5. 设置母核位置、初始状态、正常武器资源、放置区域与界面布局，不修改公共价格或成长规则。

菌结和器官不必使用旧地图的 `HyphaNode`、`RightNode`、`RearNode` 或 `DigestiveOrgan` 名称。网络按照真实实例登记。

根节点的 `initial_attack_organ`、`initial_digestive_organ` 可明确指定默认观察对象；未指定时从地图节点中寻找第一个对应类型。多胃囊仍独立登记并工作。这些引用仅为初始选择与显示，不限制可创建数量。

基础场景允许空地图启动，供搭建与验证；正式关卡需要按策划补齐初始防线、胃囊、资源和入口。

## 3 操作与功能配置

- `enable_colony_operations` 控制是否创建共用改向、移植及器官选择操作。
- `operations_panel_position` 与 `operations_panel_size` 可由关卡调整；共用层不强制改变窗口大小。当前测试关继续使用原设置。
- `growth_planner` 是原有生长配置，可设置地形、有限侧枝和自动接合。基础场景不擅自改变原参数；需要这些功能的正式关卡明确开启对应选项。
- `normal_weapon_profile` 用于统一本关初始和新增普通器官参数，可引用现有武器资源。
- 基础场景默认不自动出怪。关卡自己的波次或生产控制器负责安排生成。
- 更细的逐项功能限制仍由关卡实现人员按需求接入；当前开关不是完整的能力解锁配置系统。

已有供养、退款、容量、腐坏、分化、移植、修复与成长规则继续由原模块拥有，不在关卡中再实现一份。

## 4 接入关卡目标

关卡根脚本可以继承 `ColonyLevelRuntime`，目标控制器独立观察本关进度。新关不继承 `FirstLevel`，基础场景中的有限批次结束也不会自动触发胜利。

目标成立后调用：

```gdscript
level.finish_level(true, {
    "level_id": "campaign_02",
    "completed": 3,
    "total": 3,
    "target_ids": destroyed_ids.duplicate(),
})
```

- 返回值表示是否接收了新的结算请求，不表示本次立即胜利。
- 结算延后到本轮回调结束，母核死亡优先于胜利；重复目标事件不重复结算。
- 母核归零自动提出失败，不需要关卡另外操作资源。
- `level_finished(snapshot)` 发出最终结果，可由主线流程监听并播放CG或切关。
- `get_result_snapshot()` 返回独立副本，包含胜负、母核生命、有效游戏时间、累计回收、目标证据与资源快照。
- 胜负后冻结世界与系统，观察界面仍运行。主线流程节点不能放在被冻结的 `World` 或 `Systems` 下。
- 切关或释放场景时，原 `level_stopping(reason)` 通知停止业务；关卡新增的目标、生产控制器也应监听此通知并退役本局回调。

现有第一关继续使用 `FirstLevelFlow` 的六波资源；第二关通过 `AIProductionController` 独立生产并观察设施目标，接口见 `docs/第二关接入说明.md`。第三关碎片控制器仍待制作。

## 5 暂停、重开与停止

- `pause_controller` 为共用全局暂停控制器。Space 可以暂停，HUD按钮也可调用 `toggle_pause()`。
- 暂停世界与系统，保留观察界面；共用层的游戏时间不在暂停中增长。
- 根节点原有 `restart_level()` 负责业务取消、运输退役、状态重置及重载当前场景；正式场景应作为当前场景运行。
- 结算禁用玩法按钮，重开和返回菜单按钮由关卡或主线界面放在玩法HUD之外。
- 新增控制器必须停止生成、计时和回调，不能在下一关继续发事件。

使用项目对应的 Godot 4.7.2，以串行方式运行检查。例如：

```powershell
& "<Godot控制台程序路径>" --headless --fixed-fps 60 --path . --script res://tests/gameplay_foundation_test.gd
& "<Godot控制台程序路径>" --headless --fixed-fps 60 --path . --script res://tests/gameplay_legacy_navigation_test.gd
```

- `gameplay_foundation_test.gd`：空基础、两套独立命名地图、实际尸骸回收、付费新胃囊、资源守恒、暂停、目标证据副本、终局唯一性及同帧死亡优先。
- `gameplay_legacy_navigation_test.gd`：原默认入口、六个开发跳转、R重开及暂停中重开。
- 继续运行原stage11四组检查，以及改动涉及的stage10、stage9、输入、消化和战斗检查。
